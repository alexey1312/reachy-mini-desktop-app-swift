# Preview-driven snapshots and a storybook target

- Status: Implemented
- Date: 2026-08-04
- Decision record: [ADR 0002](../../adr/0002-preview-driven-snapshot-testing.md)

## Goal

Cover every ReachyUI screen in every state it can render, on iPhone and iPad, and give the same
previews a browsable home so a state can be inspected by hand.

## Shape

| Piece            | Where                                                                                   |
| ---------------- | --------------------------------------------------------------------------------------- |
| Previews         | `Sources/ReachyUI/Previews/`, excluded from the SwiftPM target                          |
| Shared wrappers  | `PreviewScene` — internal, because Prefire copies preview bodies into generated files   |
| Model fixtures   | Beside each model, under `#if DEBUG`, because they write `private` state                |
| Snapshot tests   | `Apps/ReachyUISnapshotTests` (Tuist, `product: .unitTests`, `PrefireTestsPlugin`)       |
| Storybook        | `Apps/ReachyStorybook` (Tuist, iPhone + iPad), catalogue generated by the `prefire` CLI |
| Reference images | `Apps/ReachyUISnapshotTests/__Snapshots__`, Git LFS                                     |

Two device configurations per preview — `iPhone 16 Pro` and `iPad Pro 11` — rendered from one
pinned simulator. The iPad configuration is what carries `horizontalSizeClass: .regular`.

`SpikeView` belongs to the `ReachySpike` app target, which neither the snapshot bundle nor the
storybook can import. Both compile `SpikeView.swift` and `SpikeModel.swift` in directly via source
globs in `Apps/Project.swift`, and its previews live in `Apps/ReachySpike/Previews/`. It also
carries its own `browsesLiveNetwork` flag instead of `\.reachyPreviewMode`, which is internal to
ReachyUI.

### Deliberately not covered

- `SceneViewport` in `.ready` — a bare `RealityView`; nothing renders headless.
- `CameraViewport` in `.streaming` — Metal-backed `RTCMTLVideoView`; captures as an empty rect.
- **Sheets.** `SystemUpdateCard` and `DaemonUpdateScreen` present their
  installer log in one, and `BLEConsoleScreen` its commands. What those sheets contain is
  snapshotted directly instead — `LogConsoleView` and `BLERecoveryCommandsSheet` have their own
  previews — but the presentation itself is not.

### Known wart

SwiftUI hoists `.toolbar` and `.searchable` out of the storybook's scaled cards into the app's own
bars, even though every screen preview brings its own `NavigationStack` — the limitation Prefire
records as "NavigationView in Preview not supported for Playbook". The storybook hides its root
bars, which absorbs the toolbars; `LogConsoleScreen`'s search field still floats over the
catalogue. Cosmetic, and not worth a preview-only branch inside the screen.

`SceneOptionsMenu` and `CameraMicButton` have no previews of their own: they are floating controls
that only exist over a viewport, and the viewport previews render them in place.

## Rules the implementation has to keep

1. **Frozen state.** A preview hands the screen a model already in its end state; nothing is
   awaited. `\.reachyPreviewMode` suppresses Bonjour, the log and teleop sockets, and viewport
   attachment.
2. **Nothing `private` in a preview body.** Prefire copies the body into a generated file.
3. **`mise run project` after adding a preview file.** Prefire finds previews on disk, Xcode
   compiles the list Tuist baked in; the snapshot tasks already depend on generation.
4. **No `#Preview` under a SwiftPM target.** The macro lives in Xcode's SDKs, not the pinned
   toolchain.

## Verification

```bash
./bin/mise run test         # unchanged: the package build never sees any of this
./bin/mise run test:snapshots
./bin/mise run storybook
```
